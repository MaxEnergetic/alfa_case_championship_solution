# Финансовый скоринг в FastAPI

Бэкенд использует обученную модель и адаптер отчётности из
[MaxEnergetic/alfa_case_championship_solution](https://github.com/MaxEnergetic/alfa_case_championship_solution/tree/726937544c749200e2ab65f627291aa1711062f6),
commit `726937544c749200e2ab65f627291aa1711062f6`. Модель не переобучается.
Исходные файлы адаптера сохранены в `fns_parser/scoring/upstream`, модель —
в `fns_parser/scoring/bundle`; SHA256 записаны в `bundle/manifest.json`.
При загрузке проверяются хеши, версии библиотек, список признаков и порядок классов.
Новый сервер не зависит от наличия клона в `external/`.

## Установка и запуск

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-scoring.txt
.venv\Scripts\python.exe -m uvicorn fns_parser.api:app --host 127.0.0.1 --port 8000
```

Альтернативная установка: `pip install -e ".[scoring]"`. Проверка комплекта:
`GET /api/v1/scoring/model`. При отсутствии совместимых библиотек или нарушении
целостности модели этот метод возвращает HTTP 503; обычный парсер продолжает работать.

## Скоринг по ИНН / ОГРН

```http
POST /api/v1/scoring/jobs
Content-Type: application/json

{"identifier":"5505223431"}
```

Ответ HTTP 202 содержит `job_id`, `state`, `status_url`. Опрос:
`GET /api/v1/jobs/{job_id}`. В завершённом задании `result` содержит отчётность,
признаки, проверку качества и `prediction`.

Дополнительные параметры: `year`, `as_of` (`YYYY-MM-DD`), `revision` (`main`
или точный SHA версии RFSD), `registry_job_id` (завершённое задание существующего
парсера). Для ИНН сразу запрашивается RFSD. Для ОГРН сначала разрешается ИНН через
ЕГРЮЛ/ПБ или указанный `registry_job_id`; затем сверяется ОГРН отчётности.
Если ФНС требует капчу, используются прежние `page_url`, `captcha.image_url`
и `captcha.answer_url`. Статус и отмена задания остаются в `/api/v1/jobs`.
ИП этой моделью не поддерживаются: HTTP 422.

```powershell
$job = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/v1/scoring/jobs -ContentType application/json -Body '{"identifier":"5505223431"}'
Invoke-RestMethod ("http://127.0.0.1:8000" + $job.status_url)
```

Первое обращение скачивает около 52 МБ индекса RFSD; расчёт выполняется в фоне.
Дальнейшие запросы используют локальный кэш и небольшие группы строк. Данные
источника не выдаются за прямой ответ ФНС в реальном времени. В результате
записываются версия RFSD, дата её публикации, год, URL и атрибуция CC BY 4.0.
Хеш полного Parquet сообщает источник; частичная загрузка не проверяет его целиком.

## Общий JSON анкеты

После заполнения анкеты и, при наличии, присоединения данных реестра:

```http
POST /api/v1/credit/sessions/{session_id}/scoring/jobs
Content-Type: application/json

{"revision":42}
```

`42` — пример: нужен текущий `revision` сессии. Дополнительно принимаются
`year`, `as_of`, `source_revision` (версия RFSD, чтобы не путать её с версией анкеты).
Ответ содержит `status_url` и новый `session_revision`. После завершения задания
получите свежий `GET /api/v1/credit/sessions/{session_id}/result`:

```json
{
  "data": {"company": {}, "financing": {}, "financials": {}},
  "recommendation": {"is_bank_decision": false},
  "scoring_job_id": "...",
  "scoring": {
    "status": "ready",
    "can_predict": true,
    "is_bank_decision": false,
    "prediction": {
      "probability_financial_stability": 0.8332461929823307,
      "predicted_class": 1,
      "threshold": 0.7799999999999999,
      "recommendation": "favorable_financial_profile",
      "time_period_validation": "not_validated",
      "target_financial_year": null
    }
  }
}
```

Пример сокращён. Вероятность показана для реального ИНН 5505223431, отчётности
2025 года, даты оценки 2026-10-25 и версии RFSD
`bde9b8b129a8be582b66de4e30ed79c9187a8515`.

Сохранение результата ещё раз увеличивает `revision`. Если пользователь меняет
анкету во время расчёта, результат остаётся в задании с
`session_attachment.status=stale_or_deleted_session` и не перезаписывает новую
анкету. Изменение ответа или присоединение новой выписки очищает прежний скоринг.
Обычный GET анкеты не запускает сетевые запросы. Рассчитанный скоринг хранится
в SQLite вместе с анкетой и сохраняется после перезапуска сервера.

## Входные данные и смысл результата

Вход модели — ровно 13 числовых признаков и сектор ОКВЭД из upstream
`model_code.py`, с флагами `_missing`. Коэффициенты ликвидности, капитала, прибыли,
долга, логарифмы активов/выручки и возраст рассчитываются по годовому снимку.
Медианы, ограничение значений, стандартизация и one-hot уже входят в модель.
Наш прежний общий `features.csv` не передаётся модели напрямую.

Реестровые данные могут дополнить отсутствующие дату регистрации и ОКВЭД только
если наблюдались к дате оценки. Уставный капитал не заменяет собственный капитал,
доходы ФНС не заменяют выручку РСБУ, месячные ответы анкеты не заменяют годовой отчёт.
Сумма, срок, обеспечение и цель кредита продолжают использоваться анкетой и
правилами подбора продуктов, но не попадают в эту обученную модель.

`ready` означает успешный расчёт. `insufficient_data` означает пропуски обязательных
полей, неподходящее качество, несоответствие баланса, устаревшую отчётность,
закрытую компанию или несовпадение идентификаторов. `source_unavailable` — сбой
источника, `model_unavailable` — ошибка загрузки/выполнения модели. В этих случаях
`prediction=null`, а не нулевой балл или отказ в кредите.

Вероятность относится к заданному авторами правилу финансовой устойчивости.
`probability_financial_distress=1-p` относится только к отрицательному классу
этого эксперимента, а не ко всем возможным проблемам и не к кредитному дефолту.
Порог 0.78 экспериментальный. Обучение: отчётность 2023 года на 2025-01-11,
исходы за 2025 год. Для других периодов возвращается
`model_not_validated_on_this_time_period`, горизонт прогноза не придумывается.
Скоринг не изменяет `recommendation` анкеты на «выдать/отказать».

## Настройки и проверка

* `SCORING_CACHE_DIR` — кэш (по умолчанию `data/scoring_cache`).
* `SCORING_TIMEOUT` — таймаут одного сетевого запроса, по умолчанию 45 секунд.
* `SCORING_RFSD_REVISION` — `main` или точный SHA.
* `SCORING_OFFLINE=true` — только кэш; необходимы явные SHA и год.
* `SCORING_MAX_REPORT_AGE_DAYS` — максимум возраста отчёта, по умолчанию 730 дней.

```powershell
.venv\Scripts\python.exe -X utf8 -m unittest tests.test_scoring tests.test_credit tests.test_api -v
```

Проверяются совпадение с опубликованным прогнозом настоящей модели, единицы,
пропуски, качество данных, идентификаторы, интеграция заданий и сохранение сессий
при одновременном редактировании. Модель не переобучается во время тестов.
