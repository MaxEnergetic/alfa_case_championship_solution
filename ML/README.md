# Модель финансовой устойчивости: первый эксперимент

## Бэкенд FastAPI

В [backend/](backend/README.md) находятся API анкеты, сбор данных ФНС с ручной
капчей, подготовка датасетов и интеграция обученной модели. [Контракт скоринга](backend/docs/scoring-api.md).

Из корня репозитория (Python 3.12):

```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements-scoring.txt -e .
python -m uvicorn fns_parser.api:app --host 127.0.0.1 --port 8000
```

Swagger: http://127.0.0.1:8000/docs. Локальный MVP работает с одним процессом
Uvicorn; авторизация пока не реализована. Кеши, базы сессий и выгрузки компаний
создаются локально и не входят в репозиторий.

Модель обучена на финансовых признаках, доступных 11.01.2025, и целевой разметке по отчётности за 2025 год. Входная отчётность — за 2023 год из зафиксированной версии RFSD, опубликованной 10.01.2025. Исход — на 31.12.2025, из версии RFSD 3.1.0, опубликованной 02.09.2026. Это один временной срез. Это не оценка состояния компаний на сегодняшний день.

## Разметка в dataset_raw.csv

- `target_financial_stability=1`: капитал > 0, чистая прибыль > 0, оборотные активы >= краткосрочных обязательств в 2025 году.
- `target_financial_stability=0`: капитал < 0 ИЛИ одновременно чистая прибыль < 0 и оборотные активы < краткосрочных обязательств.
- Все четыре показателя должны быть известны. Промежуточное состояние, пропуски или неприемлемое качество отчётности оставлены без метки: значение 0, соответствующий `_missing=1`.
- Для качества исхода проверены filed=1, financial=0, imputed=0, outlier=0, articulated=1, неотрицательные суммы активов и пассивов и равенство баланса с допуском 1 000 руб. Флаг totals_adjustment сохранён: источник может корректировать бухгалтерские суммы.
- Для обучения дополнительно проверены наличие исторического среза, качество исходной отчётности, положительные исходные активы и баланс. Известное банкротство до даты признаков исключает строку из обучения.
- `stability_label_reason` объясняет метку или её отсутствие. `financial_stability_training_eligible=1` — допуск строки в этот эксперимент. `stability_training_split` содержит train/test/excluded.
- Все `outcome_*`, целевые метки, источники, даты исхода и прочие служебные поля запрещены на входе модели. Полный белый список признаков находится в model_code.py.
- Поля экспертной оценки, банковского дефолта и решения о финансировании не заполнялись. Автоматическая метка финансового состояния не равна фактическому «давать / не давать».

Всего 11 076 строк и 690 колонок. Метки: 3 316 положительных, 1 515 отрицательных, 6 245 неизвестных. Для обучения допущено 4 702 компании: 3 248 положительных и 1 454 отрицательных. Остальные 129 размеченных строк исключены из обучения по качеству признаков.

## Обучение и проверка

Логистическая регрессия с L2-регуляризацией. Использованы 13 числовых признаков и сектор ОКВЭД. Числовые признаки ограничиваются 1-м и 99-м процентилями, пропуски заполняются медианой с индикаторами, затем выполняется стандартизация. Сектор кодируется one-hot. Все преобразования обучаются только внутри обучающей части каждого CV-разбиения. Реальные нули отличаются от пропусков.

3 761 компания — обучение, 941 — отложенная проверка, ИНН не пересекаются. Разбиение стратифицированное, seed=42. На обучении выполнена 5-кратная CV по log loss для C=[0.01, 0.1, 1, 10]; выбрано C=0.1. Порог 0.78 выбран по balanced accuracy на out-of-fold прогнозах обучающей части. Эти OOF-прогнозы используют C, уже выбранный на обучающей части, поэтому итоговую оценку даёт только отложенная выборка. После проверки модель не переобучалась на тесте.

На 941 отложенной компании: ROC-AUC 0.8659; balanced accuracy 0.7905; accuracy 0.8023; log loss 0.4030; Brier score 0.1237. Матрица ошибок (истинный класс по строкам, прогноз по столбцам, порядок 0/1): [[221,70],[116,534]].

Сравнение с простым сохранением исходного финансового состояния: правило смогло дать однозначный ответ на 803 тестовых компаниях (85.3%). На ЭТОЙ ЖЕ подвыборке его balanced accuracy = 0.8249, у модели = 0.8229; accuracy правила = 0.8742, у модели = 0.8630. Преимущество ML над этим правилом пока не подтверждено. Эти показатели подвыборки нельзя сравнивать напрямую с показателями модели на всех 941 компаниях.

Порог 0.78 — экспериментальный порог финансовой классификации, не утверждённый порог выдачи кредита. Вероятность относится к определённому правилом классу среди компаний с наблюдаемыми и однозначными исходами. Промежуточные состояния и отсутствие будущей отчётности создают ограничение применимости. Проверки на следующем календарном периоде пока нет. Состав исходной базы и специально подобранные контроли не являются случайной выборкой всех заёмщиков. Отраслевые результаты доступны в metrics.json. Отсутствуют ответы анкеты, поэтому сумма, срок, цель и обеспечение финансирования не оценивались.

## Файлы

- model.joblib — обученная модель вместе с преобразованиями.
- model_code.py — белый список признаков и преобразования; нужен при загрузке model.joblib.
- label_rules.py — повторный расчёт и проверка всех меток по сохранённым значениям исхода.
- train.py — воспроизводимое обучение на сохранённом CSV.
- predict.py — воспроизведение прогнозов отложенной выборки из этого CSV.
- weights.json — найденные коэффициенты, свободный член и параметры преобразований. Коэффициенты относятся к преобразованным признакам: это не проценты важности и не веса сырых сумм в рублях. Корреляции признаков не позволяют трактовать коэффициенты как причинное влияние.
- metrics.json — метрики, сравнения, параметры и ограничения.
- split_map.json — закреплённое разбиение по ИНН.
- holdout_predictions.json — фактические классы и прогнозы тестовых компаний.
- data_audit.json — количества и причины исключений.
- source_manifest.json — источники, версии, даты доступности, единицы и атрибуция.
- requirements.txt — версии зависимостей. Эксперимент выполнен на Python 3.12.

## Запуск

Распакуйте архив в папку рядом с dataset_raw.csv. В этой папке, в окружении с зависимостями из requirements.txt:

```bash
python label_rules.py --input ../dataset_raw.csv
python predict.py --input ../dataset_raw.csv --output predictions.json
python train.py --input ../dataset_raw.csv --output retrained
```

Для загрузки из Python запускайте код из папки с model_code.py:

```python
import joblib
from model_code import make_features
model = joblib.load('model.joblib')
# df — строки CSV, прочитанные как строки, вместе с *_missing.
probabilities = model.predict_proba(make_features(df))[:, 1]
```
