# Данные

Gateway: `accounts`, `logins`, `credit_links`, `job_links`. Связи определяют доступ пользователя к результатам; токены хранятся только в виде SHA-256-хеша, пароли — PBKDF2 с индивидуальной солью.

Главный контракт — `SessionView` в `backend/fns_parser/credit/models.py`: `session_id`, `revision`, `state`, `next_question`, `answered_questions`, `data`, `answer_states`, `field_sources`, `conflicts`, `recommendation`, `scoring`.

`answered_questions` содержит введённые пользователем ответы и определения вопросов для редактирования. В `data` находятся итоговые значения с приоритетом сопоставимых подтверждённых полей парсера. `field_sources` и `conflicts` объясняют изменения. Годовая выручка не подменяет ответ о месячной выручке. `null` и missing-флаги сохраняют неизвестность.

`data.company` содержит реальные entities, источники, даты и выбранный ОГРН. `recommendation` не является банковским решением. `scoring.prediction` появляется только при доступной отчётности и успешной проверке входа модели. Кредитные метки, БКИ и отсутствие долгов из этих данных не придумываются.

`question_group` содержит связанные вопросы для одного экрана; `/answers/batch` проверяет все ответы и фиксирует одну ревизию либо откатывает блок целиком. `flow_version=1` сохраняет старый порядок вопросов, версия 2 группирует покупку и кредитную часть. `assessment` содержит продукты, итог с учётом финансового профиля и отдельные поля финансовой устойчивости и вероятности одобрения; последнее остаётся `null` без подходящей модели.
