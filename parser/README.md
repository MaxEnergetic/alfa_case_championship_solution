# Парсер отчётности и признаки финансовой устойчивости

Самостоятельный Python-модуль: **ИНН юридического лица → отчётность RFSD → признаки → результат существующей логистической регрессии**. Можно положить эту папку в свой репозиторий. Переобучение модели при запуске не происходит.

## Быстрый запуск

Распакуйте архив в отдельную папку, например `G:\repositories\alfa_case_championship_solution\tools\financial_enrichment`, и откройте терминал в ней. Рекомендуется Python 3.12 и отдельное виртуальное окружение.

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe enrich_company.py --inn 5505223431 --out result.json
```

В Linux/macOS путь к Python окружения — `.venv/bin/python`. Проверки выполнены в Linux на Python 3.12.14; запуск в Windows отдельно не проверялся.

По умолчанию выбираются текущая дата, актуальная версия RFSD и последний завершённый год, присутствующий в источнике. Версия разрешается в неизменяемый commit SHA и записывается в результат. Можно задать год и дату явно:

```powershell
python enrich_company.py --inn 5505223431 --year 2025 --as-of 2026-10-25 --out result.json
```

Для получения только отчётности и признаков установка ML-библиотек не нужна:

```powershell
python enrich_company.py --inn 5505223431 --no-predict --out features.json
```

Для использования уже существующего `company.compact.json`:

```powershell
python enrich_company.py --inn 5505223431 --compact company.compact.json --out result.json
```

Файл должен содержать `checked_at` (ISO-дата или timestamp) и список `entities` с ровно одной записью, у которой `inn` совпадает со строковым ИНН запроса. Из записи используются только `registered_on`, `main_okved`, `name`. Дата наблюдения не должна быть позже `--as-of`. Отсутствующий возраст/ОКВЭД можно дополнить; значения RFSD имеют приоритет. `capital_rub`, `financials.income` и `financials.expenses` не заменяют собственный капитал, выручку и прибыль бухгалтерской отчётности.

## Подключение к продукту

```python
from pathlib import Path
from alfa_financial_parser import enrich_company

# Путь к распакованному комплекту; настройте относительно своего приложения.
bundle = Path("tools/financial_enrichment").resolve()
result = enrich_company(
    inn="5505223431",                 # строка из анкеты, сохраняет ведущие нули
    cache_dir=bundle / ".cache",
    model_dir=bundle / "model",       # без model_dir API возвращает только признаки
)

if result["can_predict"] and result["prediction"] is not None:
    p = result["prediction"]["probability_financial_stability"]
    recommendation = result["prediction"]["recommendation"]
else:
    # Показать пользователю причину/запросить отчётность; не трактовать как отказ.
    reason = result.get("quality_issues", result.get("error"))
```

Для импорта папка комплекта должна находиться в `PYTHONPATH`, либо перенесите внутреннюю папку `alfa_financial_parser` в доступный приложению Python-пакет. Пути к модели и кэшу задаются независимо. Нужен ИНН юридического лица из 10 цифр с правильной контрольной цифрой. ИП с ИНН из 12 цифр не поддерживаются этой моделью. Остальные ответы анкеты автоматически не становятся признаками: для них потребуется отдельная схема и проверка модели.

Сетевой вызов выполняйте в фоновом задании продукта. Кэш переиспользуется для последующих компаний и запросов. В этой версии нет HTTP-сервера и массовой очереди обхода.

## Что возвращается

`result.json` содержит:

| Поле | Содержимое |
|---|---|
| `status`, `can_predict` | Достаточность и качество данных |
| `financials_rub` | 11 исходных бухгалтерских показателей в рублях |
| `features` | 13 числовых признаков, секция ОКВЭД и флаги пропусков |
| `registry` | ОГРН, дата регистрации, ОКВЭД, дата ликвидации при наличии |
| `source` | Источник, год, commit SHA, дата доступности версии, время получения |
| `missing_core_fields`, `quality_issues`, `warnings` | Причины блокировки и оговорки |
| `prediction` | Вероятность, бинарный класс, порог и рекомендация; иначе `null` |

`ready` означает, что данные прошли проверки; с `--no-predict` прогноз всё равно равен `null`. `insufficient_data` означает отсутствие компании/обязательных данных либо провал проверок; `source_unavailable` — ошибку получения источника. CLI также возвращает `error` при ошибках ввода или несовместимом формате. Коды завершения: `0` — ready, `2` — insufficient_data, `3` — ошибка. API возбуждает `ValueError` при некорректном вводе; ошибки источника возвращает структурированным результатом. Ошибки неподдерживаемого формата/повреждения файлов также могут возбуждать исключения.

Неизвестное значение признака записывается как `0` с `<признак>_missing=1`. Настоящий ноль имеет `missing=0`. В исходных `financials_rub` неизвестное значение остаётся `null`. Нулевой знаменатель означает пропуск коэффициента. Отрицательные прибыль и собственный капитал сохраняются как данные.

Признаки: текущая ликвидность, капитал/активы, чистая рентабельность, ROA, деньги/активы, `log1p` активов и выручки, возраст компании, обязательства/активы, операционная прибыль/модуль процентов, признаки отрицательного капитала, убытка и отрицательного оборотного капитала, секция ОКВЭД. На вход модели передаются ровно эти признаки и флаги, а не вся исходная таблица из сотен столбцов.

Для прогноза обязательны строки 1200, 1300, 1500, 1600, 1700, 2110, 2400, дата регистрации и секция ОКВЭД. Отсутствие строк 1250, 1400, 2200, 2330 обрабатывается пропусками. Проверяются положительные активы, совпадение 1600 и 1700 с допуском 1000 рублей, допустимые знаки показателей, даты, отсутствие ликвидации на дату оценки и качество RFSD: `filed=1`, `financial=0`, `imputed=0`, `outlier=0`, `articulated=1`. Корректировки итогов источником дают предупреждение.

Отчётность старше 730 дней после конца отчётного года блокируется; настройка `--max-report-age-days`. Это политика полноты данных, а не обученный параметр. Отсутствие данных не приравнивается к финансовой неустойчивости.

## Источник и загрузка

Используется открытый [RFSD](https://huggingface.co/datasets/irlspbru/RFSD/blob/main/README.md), содержащий годовые данные Росстата/ФНС. Это годовые снимки, а не прямое обращение к ГИР БО ФНС в реальном времени. Прямой запрос к ФНС во время разработки вернул HTTP 503; проверенного адаптера ФНС в комплекте нет. Не каждая компания обязана или успела представить пригодную для модели отчётность.

Через [публичный API Hugging Face](https://huggingface.co/docs/hub/api) определяется файл и версия. По статистике групп строк в [Parquet](https://parquet.apache.org/docs/file-format/) находятся группы, содержащие нужный ИНН, затем скачиваются диапазоны байтов и проверяется точное совпадение ИНН. Для снимка 2025 года метаданные занимают около 52 МБ при первом обращении; затем они кэшируются, а размер нужной группы существенно меньше. Весь годовой файл около 534 МБ не требуется. Объёмы зависят от версии источника.

Реализован небольшой декодер плоской схемы RFSD, включая используемые кодеки и кодировки. Это специализированный адаптер, а не универсальная библиотека Parquet. При изменении схемы/разбиения файла понадобится обновление. `reported_file_sha256` — хеш полного файла, сообщённый источником: загрузка диапазона не проверяет хеш всего файла. Проверяются HTTP 206, Content-Range и длины ответов; используется стандартная HTTPS-проверка сертификата. Неуспешные запросы не заменяются выдуманными данными.

Для воспроизводимости передавайте `--revision` с SHA из `source.revision`. Для истории нужна версия, уже доступная на дату `--as-of`: последняя версия не выдаётся за исторически доступную. Автоматического поиска старой версии или отката к более ранней отчётности нет.

После первого успешного запроса можно использовать тот же кэш без сети:

```powershell
python enrich_company.py --inn 5505223431 --year 2025 --as-of 2026-10-25 --revision bde9b8b129a8be582b66de4e30ed79c9187a8515 --offline --out result.json
```

Параметры `--cache-dir` и `--timeout` позволяют задать каталог и таймаут запроса. Запросы повторяются один раз только при временных сетевых ошибках/502/503/504. Ограничения доступа не обходятся.

Данные RFSD: CC BY 4.0. Атрибуция: Bondarkov, Ledenev, Skougarevskiy, *Russian Financial Statements Database*, [doi:10.1038/s41597-025-05150-1](https://doi.org/10.1038/s41597-025-05150-1). Сохраняйте атрибуцию при распространении извлечённых данных.

## Модель и смысл результата

В `model/` находится ранее обученная L2-логистическая регрессия scikit-learn, `C=0.1`, со своим препроцессингом и экспериментальным порогом 0.78. Используется `predict_proba`, обучение не запускается. Загружайте только доверенные файлы модели: формат joblib выполняет Python-десериализацию.

Положительная обучающая метка: последующие собственный капитал и чистая прибыль положительны, оборотные активы не меньше краткосрочных обязательств. Отрицательная: отрицательный капитал либо сочетание убытка с недостатком оборотных активов. Промежуточные и неизвестные исходы не были отрицательным классом. Поэтому дополнение `1-p` относится к отрицательному классу этой задачи, а не ко всем возможным финансовым проблемам.

Обучение использовало отчётность 2023 года, доступную к 2025-01-11, и результат 2025 года. Проверка была на других компаниях той же исторической когорты. При другом годе/дате появляется `model_not_validated_on_this_time_period`, а `target_financial_year=null`: качество и горизонт для нового периода не установлены. Вероятность — оценка класса финансовой устойчивости по принятому определению, не вероятность возврата кредита и не статистическая уверенность в правильности ответа. Рекомендации: `favorable_financial_profile` / `financial_risk_review`.

## Проверки и пример

python -m unittest discover -s tests -v

Пройдены 24 автономных теста. Дополнительно проверены расчёты на 941 компании исходной тестовой выборки: максимальное различие вероятностей — около `2.35e-10`, вследствие округления обучающего CSV. Более строгую проверку полноты этого адаптера прошли 880 из 941 компаний: для остальных прогноз не возвращается. Проверка совпадения вычислений не заменяет оценку качества модели на новых периодах.

В `examples/company_5505223431.json` — реальный результат загрузки 2025 года на дату 2026-10-25. Проверены автоматический выбор года и повторный офлайн-запуск. При сетевой проверке использовались ранее полученные метаданные неизменяемого файла; группа строк компании загружена новым клиентом. Полный первый запуск с пустым кэшем отдельно не проверен. Подробности — `validation.json`.
